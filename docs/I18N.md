# komponist – Internationalisation (i18n)

How the UI texts are stored, generated and used. Background and the decisions behind it:
`docs/I18N-EVALUATION.md` (§14 holds the owner's decisions of 2026-11-15). Languages today: German (source)
and English (draft).

## 1. How it works

`crates/komponist-i18n` is a leaf crate. Its `build.rs` reads `locales/<lang>/*.ftl` (Project Fluent syntax) and
generates the Rust API at build time:

```text
crates/komponist-i18n/
  locales/de/<area>.ftl     German, the source language (verbatim from the screens, CLAUDE.md rule 1)
  locales/en/<area>.ftl     English: the same keys and the same variables
  generator.rs              the generator (used by build.rs and by the golden tests)
  build.rs                  reads the folders, writes $OUT_DIR/catalog.rs, stops the build on errors
  src/lib.rs                Count, Plural, the plural rule of each language, Lang::from_code
  tests/it/                 golden tests of the generator, tests of the generated API
  tests/fixtures/locales/   a small catalog the tests compile to try plurals, variables and terms
```

Generated (`komponist_i18n::`):

| Item | Meaning |
|---|---|
| `Lang` | `Copy` enum, one variant per folder (`De`, `En`); `Lang::default()` is `De`; `Lang::ALL`, `code()`, `from_code("de_DE.UTF-8")` |
| `t.dock_devices()` | static text: `&'static str` |
| `t.status_clips_selected(n)` | text with variables or plurals: `String`; a selector variable is `impl Count`, any other `impl Display` |
| `Lang::by_id("undo-duplicate-clips")` | `Option<&'static str>` for a stored message id (undo labels); static messages only |
| `de::DOCK_DEVICES`, `en::DOCK_DEVICES` | the static texts as constants, for tests and `match` patterns |

Rustdoc of every method shows the `.ftl` comment and the German and English text, so hover in the editor tells
what a message is.

### Use in code

```rust
// A view (komponist-app): ViewCtx carries the language.
let t = cx.lang;
w::Button::new(t.dock_maximize()).show(ui);
node.set_label(t.a11y_clip(&clip.name, first, last));          // text with variables: String

// A widget that owns texts (komponist-ui): the language lives in the egui Context.
let t = komponist_ui::lang(ui.ctx());

// A test: German is the default and the test language.
h.get_by_role_and_label(Role::Button, de::DOCK_COLLAPSE);        // static texts
assert_eq!(Lang::De.status_clips_selected(2), "2 Clips ausgewählt");
```

`App::new` always starts in German and never reads the environment. `main()` resolves the language
(`--lang de|en`, else `Settings.language`: `system`, `de` or `en`; `system` is German on a German desktop and
English otherwise, read with `sys-locale`) and calls `App::with_lang`. Each frame the app writes the language into
the egui `Context` (`komponist_ui::set_lang`), so tests in one binary do not share it.

## 2. Files and keys

- One file per area, so parallel work touches different files: `shell`, `transport`, `status`, `keys`,
  `arrangement`, `piano-roll`, `step-seq`, `browser`, `devices`, `mixer`, `inspector`, `dialog-*`, `plugin-frame`,
  `undo`, `format`, `a11y`, `builtin`, `dock` (pilot).
- **Keys** are kebab-case, `<area>-<name>`: `dock-no-clip`, `file-open-title`. They become `dock_no_clip()` and
  `de::DOCK_NO_CLIP`. Do not name a key like a Rust keyword (`type`) or like a `Lang` method (`code`, `plural`,
  `by-id`); the build says so.
- A key exists once, in every language, in the file of the same name. Variables are the same in every language.
- Every message has a `#` comment with its design source (`S09 recent header`, `Designsystem tab`). Group
  headers use `##`.
- Variable names are snake-friendly (`$clip_name` or `$name`); the parameter order of the method is the order of
  first appearance in the **German** text.

## 3. Add a message

1. Add it to `locales/de/<area>.ftl` with a `#` comment: the German text, verbatim from the screens.
2. Add the same key and variables to `locales/en/<area>.ftl` (style guide, §6). The build fails otherwise.
3. Use it: `t.area_name()`. Run `cargo check -p komponist-i18n` to see the generator's errors first; they name
   file and line.

### The supported Fluent subset

| Construct | Example | Note |
|---|---|---|
| text | `dock-mixer = Mixer` | multi-line values work as in Fluent |
| variable | `greeting = Hallo { $name }` | values are formatted in Rust (`fmt_db`, `fmt_pos`, …) and passed in |
| string literal | `braces = { "{" }Text{ "}" }` | for `{`, `}` and leading or trailing spaces |
| term | `{ -komponist }` | plain text only, substituted at build time; define it in each language that uses it |
| plural select | `{ $n -> [0] Keine *[other] { $n } }` | selector is a variable; keys are integers or CLDR categories (`zero`, `one`, `two`, `few`, `many`); `*[other]` is required and the only default |

Errors (all with file and line): key missing in a language, key only outside German, different variables, select
without `*[other]`, anything else (attributes, message references, functions such as `NUMBER()`, number literals,
non-plural select keys, terms with variables or arguments), syntax errors, duplicate keys, keys that clash with a
Rust keyword or a `Lang` method.

Plurals are selects, never `if n == 1` in Rust:

```ftl
status-clips-selected =
    { $n ->
        [one] 1 Clip ausgewählt
       *[other] { $n } Clips ausgewählt
    }
```

## 4. Add a language

1. Create `locales/<code>/` (lower-case code: `fr`, `pt-br`) and copy every `.ftl` file of `de/`. `cargo build -p
   komponist-i18n` lists everything still to translate.
2. **Plural rule.** `Lang::plural` in `crates/komponist-i18n/src/lib.rs` is a `match` over all languages; the build
   fails with "non-exhaustive patterns" until the new language has an arm. That arm is the only code a language needs:
   - one, other (German, English, Spanish, Italian, …): `Plural::germanic(n)`;
   - others: write the CLDR rule (https://unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html),
     for example Polish `n == 1 → One`, `n % 10 in 2..=4 && n % 100 not in 12..=14 → Few`, rest `Many`/`Other`; or call
     `icu_plurals` (ICU4X, Unicode licence) and map its categories to `Plural`. The generator already emits arms for
     `[zero] [one] [two] [few] [many]`, so no generator change is needed.
3. Add the language to `Language` in `komponist-app/src/settings.rs` (the settings enum, `resolve`) and to the row in
   S07 "Darstellung" (WP-77). `--lang <code>` and the system language pick it up through `Lang::from_code`.
4. Check the fonts: IBM Plex covers Latin, Cyrillic and Greek; CJK, Arabic, Hebrew, Devanagari and Thai need more
   (`docs/I18N-EVALUATION.md` §7.10). Right-to-left needs bidi support in egui first.

## 5. What not to translate

- **Names:** komponist, pisynth, klopfer; plugin names and vendors; CLAP, VST3, MIDI; PipeWire, JACK, ALSA; device
  and port names from the system.
- **User content:** project, track, clip, take, step-row and pattern names, file names, paths. Default names
  ("Unbenannt", "Take 3", "Pattern 2") are made in the current language when they are created and are content
  afterwards, saved in the project and never retranslated. The demo project "Nachtfahrt" is content.
- **Plugin-provided text:** parameter names, value texts, preset names, plugin log lines.
- **Values and notation:** note names are **C D E F G A B** everywhere (no German H), C4 = 60; positions (10.2.120),
  times (00:17.902), dB, pan (C, L 12, R 50), decimal point and U+2212 minus, units (dB, dBFS, Hz, kHz, ms, s, BPM),
  key letters and digits in shortcuts. These are formatters in Rust, passed into messages as arguments.
- **Developer-facing text:** log lines, CLI usage and errors, internal `Display` texts, egui ids, test-plugin names.
  English code, commits and docs stay English.
- **The gallery** (`komponist-gallery`) keeps literal German; it mirrors the design system page.
- **English terms in the German design are still catalog texts** (identical in `en`): Piano Roll, Step Sequencer,
  Mixer, Inspector, Browser, Loop, Snap, Velocity, Swing, Ratchet, Take, Bypass, Solo, Mute, Record-Arm, Monitoring.

## 6. Style guide

### German (source)

Verbatim from `Screens.dc.html`, including typography: „…“ quotes, U+2212 minus, " · " separators, en dash in
ranges, "…" after a space for actions that need more input ("Projekt öffnen …"), "35 %" with a space, keys as
"Strg Shift E", time "heute 09:12". The DAW is **komponist**, not "klang-studio".

### English (US)

| Topic | Rule |
|---|---|
| Spelling | US English: Color, Center, Canceled, Gray |
| Capitalisation | **Title Case** for titles, buttons, tabs, menu items and dialog headings ("Open Project…", "No Clip"); **sentence case** for labels, tooltips, accessible names of icon-only buttons, status texts and hints ("Collapse dock", "No track armed") |
| Quotes | “curly” (U+201C … U+201D) around names; never „ in `en` |
| Ellipsis | U+2026 without a space before it, for actions that need more input: "Open Project…" |
| Percent | "35%" (no space) |
| Time | 24-hour: "today 09:12", "yesterday", "5 minutes ago", "Oct 12", "Oct 12, 2025" |
| Shortcuts | "Ctrl+Shift+E", "Space", "Del", "Backspace", "Home", "End"; letters, digits, arrows, `+`, `−`, `[`, `]`, `,` as they are |
| Ranges | en dash: "Bars 1–4" |
| Values and units | unchanged: "−3.2 dB", "120 BPM"; the space before the unit stays |
| Wording | short, active, imperative on buttons ("Save", "Export…"), no "please", no exclamation marks |
| Never | ASCII `...`, ASCII hyphen as a minus before digits |

## 7. For volunteer translators

You need a text editor, the repository and a Rust toolchain; no Rust knowledge.

1. Copy the folder of an existing language that is complete (`crates/komponist-i18n/locales/en`) or start from
   `de`, and edit the `.ftl` files. One message is `key = text`; the line above it (`# …`) says where the text
   appears. Keep the key and every `{ $variable }` exactly as in German; change only the words around them.
2. Keep `{ … }` pairs closed. For counts, write one variant per plural form your language needs
   (`[one]`, `[few]`, `[many]`, `*[other]`; see the CLDR link above); `*[other]` stays last and marked with `*`.
3. Follow the style guide for your language; do not translate §5's names and values.
4. Run `cargo build -p komponist-i18n`. A missing key, a changed variable or a syntax error stops the build and
   names the file and line. Fix it and build again; `cargo test -p komponist-i18n` runs the generator's tests.
5. Start komponist with `scripts/run.sh --lang <code>` to see the result.

A new language also needs its plural rule in `src/lib.rs` (§4); ask a developer if you are unsure. A translation
platform (Weblate or Pontoon) follows when the repository is public; `.ftl` stays the source format.
